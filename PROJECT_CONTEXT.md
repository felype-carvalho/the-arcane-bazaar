# Project context and business rules

This document describes the behavior **currently implemented** in The Arcane Bazaar. It is a reference for changes made by people or AI. When a rule changes, update the relevant section and check the linked code and tests. The implementation remains the source of truth.

## Purpose

The application presents a catalog of D&D items and calculates buying and selling prices for campaigns. Calculated prices are a campaign aid, not official rules. The interface supports English and Brazilian Portuguese. Catalog content is translated at presentation time, with the original English text as the per-field fallback.

## Interface language

The toolbar's system-menu button uses the Lucide Menu icon.

The Wizard Pouch logo appears to the left of the project title in the toolbar and is used as the browser-tab icon. Both locations resolve the logo relative to the application deployment base path. The toolbar uses `wizard-pouch.svg`; the browser-tab icon provides `wizard-pouch.svg` and `wizard-pouch.png`. Both assets use the artwork from `.docs/logo-concepts/`, enlarged proportionally within the original 512 × 512 canvas to reduce transparent margins. The PNG is rendered from the SVG to keep both versions consistent.

- The toolbar's system menu shows Language directly below Settings and above About, with the same menu-row styling. Hovering Language opens an English / Português submenu to the left; clicking or tapping also opens it. The current language is marked. Keyboard users can open it with Enter, Space, Left, or Down, navigate choices with Up/Down or Home/End, and return to Language with Right or Escape. Selecting a language closes both menus. The initial language is `pt-BR` for a Portuguese browser and `en-US` otherwise. A valid choice stored in localStorage under `the-arcane-bazaar:language` takes precedence; absent, invalid, or inaccessible storage falls back to the browser language.
- Language changes apply immediately, including open dialogs, status and validation messages, accessibility labels, document language, and browser-tab title. If localStorage cannot be written, switching still works for the current session. English is the translation fallback.
- Type, rarity, category, structured field labels, and pricing modifier labels are translated only for presentation. Internal IDs, filter values, source codes, artwork resolution, variant selections, and pricing formulas remain unchanged. The community glossary is used contextually, preferring 2024 terminology when available and otherwise 2014 terminology.
- Portuguese labels preserve the capitalization style of their English counterparts. Title-style terms capitalize their main words (for example, `Adventuring Gear` becomes `Equipamento de Aventura`), while Portuguese prepositions and conjunctions remain lowercase.
- Item names and available prose translations follow the selected language. Publication names, user profile names, and custom modifier names remain unchanged. Recognized measurements in subtypes, descriptions, and other item-specific content follow the active profile's measurement preferences. The internal `default` profile is displayed as `Default` or `Padrão`. Catalog search accepts both Portuguese and English names, and name sorting uses the displayed name and selected locale.
- Numbers and currency displays use the selected locale. Portuguese uses PO/PP/PC; English uses GP/SP/CP. Prices and manual price inputs still represent GP internally.
- Language is global, independent of profiles, and excluded from backups. Importing a backup does not change the language. A successful local-data reset removes the saved language preference and returns to the browser language.

Translation text is maintained in separate [English](src/app/i18n/locales/en-US.json) and [Portuguese](src/app/i18n/locales/pt-BR.json) JSON files with matching semantic keys, such as `toolbar.settings`. Internal labels and stored error messages are mapped explicitly to these keys, so editing English wording does not change the lookup identifiers. Tests verify key and interpolation-placeholder equivalence between both languages.

References: [language configuration](src/app/i18n/index.ts), [translation resources](src/app/i18n/resources.ts), [internal label mapping](src/app/i18n/label-keys.ts), [language tests](src/app/i18n/i18n.test.tsx).

### Catalog translations

- Catalog resources are separate from interface labels, in `src/features/catalog/data/translations/pt-BR/`. `items.json` contains names by stable item ID, `item-texts.json` contains item-specific source-text translations by stable item ID, and `shared-texts.json` contains exact source-text translations reused across items. `index.ts` combines these resources into the same typed catalog used by presentation and the coverage report. All resources are imported eagerly. A changed source passage falls back to English until its translation is updated.
- Original catalog objects remain the input to classification, filtering by internal values, selection, pricing, and artwork lookup. Presentation copies translate only visible text. Language changes update open sheets and accessibility labels without reloading artwork or resetting selected options and pricing modifiers.
- Hovering item names in the desktop/mobile catalog, details panel, and item-sheet heading shows the shared tooltip with English and Portuguese names, independent of the active interface language. Selected version/base selectors and the selected base-price card also provide these bilingual tooltips. Names use stable IDs and the usual English fallback for missing Portuguese translations; proper names still appear under both language labels when identical. Native select menus retain their existing option text; the tooltip describes the selected option.
- Generic families, group members, inferred initial stages, and compatible base options have explicit display names. Portuguese family terminology stays consistent across the group, its versions, and compatible bases; Enspelled Weapon, Armor, and Staff use Arma Encantada, Armadura Encantada, and Cajado Encantado. Specific variants without an independently translated name use the reviewed family name followed by the base name in parentheses, stored under the specific variant ID. The inferred initial-stage option is displayed as `Initial` or `Inicial` and stays first. Other group options sort by ascending canonical rarity, then by their translated labels using the selected interface locale. Base options retain source priority and sort by translated name within each source.
- Description tables retain their original block order, dimensions, and numeric cells. Translated prose keeps machine-readable original measurements for the existing measurement renderer. Original paragraph and table-row context is supplied for ambiguous units such as ounces. Structured travel and shipping costs keep their original values for the existing currency and denominator conversion renderer.
- Numeric and dice-only table headings and cells remain on one line, including `d100` and roll ranges. Prose cells can wrap; wider tables scroll inside their existing container on narrow screens.
- Translation generation happens during development only. The browser uses versioned local resources and makes no translation-service requests. Glossary terminology prefers 2024 and falls back to 2014. Missing translations remain English.
- Portuguese prose uses the registered Portuguese item names for self-references and references to other catalog items, with contextual articles, pronouns, agreement, and plural forms. English lookup keys, proper names that are intentionally preserved, and machine-readable measurements remain unchanged.
- The current catalog snapshot has Portuguese resources for every visible name and applicable prose, structured value, table heading, and text cell. Proper names, Portuguese cognates, card notation, and measurement data can deliberately remain unchanged. Development review records distinguish individual source rewrites from source-conditioned terminology checks and automated validation; they do not imply a separate manual editorial pass over every sentence.
- `npm run translations:report` regenerates the per-item coverage report and pending batches under `.docs/`. It reports names separately from text fields, records each field as translated, reviewed unchanged, preserved data, or pending, and records hashes of the immutable source files. Numeric cells, dice expressions (including bare dice such as `d100`), and standalone measurements are preserved data. Pending passages are grouped by source and item family in batches of at most 25, retaining references to every affected item. Translation tests verify resource IDs, source-text validity, numbers, dice, measurements, table structure, bilingual search, and presentation-only behavior.
- `npm run translations:check` generates the same report and fails if any name or applicable visible text field is missing. The report and tests use the same field inventory and preserved-data classifier. Tests also reject unresolved translation markers and corrupted text, verify table-heading measurement units, and require complete coverage of the current immutable catalog snapshot. Future or revised source passages still fall back to English at runtime until their resources are updated.

## Catalog and data sources

- The catalog is built from `items.json`, `items-base.json`, and `magicvariants.json` in `src/features/catalog/data/`. Item artwork is loaded separately from `fluff-items.json` when an item sheet opens. These files are immutable inputs: transformations and presentation fixes belong in the processing code, without rewriting the source files.
- Loading validates the required structure of all three files, resolves internal references and copies, normalizes the items, and caches the complete operation. A failed load can be retried later.
- Copy modifications support removing array elements by name or exact value (`removeArr`), replacing elements by name, exact value, index, or regular expression (`replaceArr`), and replacing text in selected entry properties (`replaceTxt`). Regular-expression array selectors match section names or plain-string elements. Text replacement is global, supports regex flags and nested entry content, and preserves inline 5etools tags unless `tagInsensitive` is explicitly enabled. Operations run in source order without mutating the original records; missing required targets and unsupported operations fail catalog construction. Forced name removals may skip missing names.
- The catalog distinguishes common items, magic items, item groups, base items, and generic variants. A specific variant is built for each valid generic-variant/base-item combination, while the catalog displays the generic family once with compatible base items as options.
- Each catalog item has a stable ID derived from its origin, source, and name; variant combinations also include the base and variant. ID collisions and invalid options stop catalog construction.

References: [loading](src/features/catalog/model/items/load-json.ts), [catalog construction](src/features/catalog/model/items/build-catalog.ts), [normalization](src/features/catalog/model/items/normalize-item.ts).

## Item classification and presentation

- A base item or a record whose original rarity is `none` or `unknown` is classified as `Common`; all other records are classified as `Magic`. Displayed rarity is normalized to the `Rarity` values; unrecognized values become `Unknown`.
- Every item has one primary category and may belong to additional categories. Explicit exceptions and structured fields determine the primary category first; the name and description help classify the item when needed. Markers such as `Cursed`, `Consumable`, and `Wondrous` may add secondary categories. `Other` is the fallback.
- An explicit price in the JSON is expressed in hundredths of a GP and converted to GP. If it is absent, estimated prices by rarity are: `Common` 100 GP, `Uncommon` 400 GP, `Rare` 4,000 GP, `Very Rare` 40,000 GP, and `Legendary` 200,000 GP. Other rarities have no estimated price. An explicit price of zero is preserved and marked as explicit.
- Availability derived from rarity is `Available` for `None`, `Common`, and `Uncommon`; `Limited` for `Rare` and `Very Rare`; and `Unavailable` for the remaining rarities. This value exists in the model, but the current filtering function **does not apply it as a filter**.
- A valid subtype appears below the item name on the item sheet, except for items in the `Trade Good` primary category: their subtype appears at the start of the Description section, even when they have no other description text. Numeric weight is stored as pounds (`lb`) and displayed using the active profile's weight preference. Attunement is required when `reqAttune` is true or contains text. Textual requirements, source page, weapon/armor information, and description paragraphs appear on the item sheet when valid data exists; missing fields are not invented. Weapon card values and each name in equipment property lists start with an uppercase letter. When a weapon has an ammunition type, its Ammunition property shows that type in parentheses (for example, `Ammunition (Bolt)`). Light armor displays its base AC with `+ Dex` (for example, Studded Leather Armor is `12 + Dex`); medium armor includes the maximum Dexterity modifier (for example, Chain Shirt is `AC 13 + Dex (max 2)`). Base damage and armor class appear in their equipment cards rather than being repeated at the end of the description. Armor with a Stealth penalty or numeric Strength requirement includes the corresponding rule text in the description as well as the structured card. Equipment cards use three columns on wide screens, two on intermediate screens, and one on narrow screens.
- Vehicle items display a Vehicle Information section when structured data exists. It can show speed in mph, cargo tonnage and passenger capacity, crew (including ranges), AC, HP, damage threshold, personal travel cost per mile per passenger, and shipping cost per 100 lb per mile. Cost fields are converted from hundredths of a GP. Missing fields are omitted, and vehicles with no structured specifications do not show the section.
- Mount items display a Mount Information section with speed in feet and carrying capacity in pounds when those values exist. The Monster Stat Block card shows the monster name from an explicit stat block reference in the description, or the item's name when no such reference exists. Missing speed and capacity values are omitted.
- Structured tables in item descriptions retain their captions, column headings, rows, and order among description paragraphs. The item sheet renders them as accessible tables with a minimum column width of 30 px, while the existing plain-text description remains available for catalog processing.
- The item sheet matches artwork by item name and source, including explicit `_copy` references in `fluff-items.json`, and uses the first image from the matching record. Artwork lookup prioritizes the selected item's own images, then its generic variant, then its explicit parent group. Group artwork is available to every referenced version and its compatible base combinations, including Enspelled families, while version-specific artwork takes precedence. Each fallback retains its original name and source and follows explicit fluff copies; missing or cyclic references terminate safely. Internal image paths point to `https://5e.tools/img/`. Artwork in the item sheet has padding around it. The image area is omitted when no image is available or the image fails to load; rarity and type badges remain visible in the summary. Selecting a real image opens a full-screen viewer with controls and keyboard navigation through all images for that item; optional artwork credits appear there. Same-name items from different sources do not share images unless an explicit copy, variant, or group relationship connects them.
- The details panel loads artwork for the effective selected item using the same lookup as the item sheet. Its first image fits inside the original 64 × 64 icon tile without cropping, preserving its border, rounded corners, background, and shadow. The original emoji remains while loading, when artwork is missing, or when loading fails. Clicking or keyboard-activating the thumbnail opens the shared full-screen image viewer with all item images, navigation, and credits; closing returns focus to the thumbnail. Changing the item, group version, or variant base resets the thumbnail and viewer and ignores stale artwork requests.
- Spellcasting Focus items show a Spellcasting Focus Information section listing eligible classes when the item has focus class data or a known focus subtype. A focus marked usable by any spellcaster, either with a true focus flag or the complete spellcaster class list, displays `Any Spellcaster`. Standard Arcane Focus, Druidic Focus, and Holy Symbol groups and their individual PHB/XPHB forms display their shared focus description before any form-specific text. The Druidic Focus requirement lists Druid and Ranger; standard focus class requirements take precedence over incomplete focus metadata.
- Every item in the Instrument category displays a Spellcasting Focus Requirement of `Bard` in the Spellcasting Focus Information section.

References: [normalization](src/features/catalog/model/items/normalize-item.ts), [categories](src/features/catalog/model/items/categories.ts), [item sheet](src/features/catalog/components/item/ItemModal/ItemModal.tsx).

## Groups and variants

- Magic groups collect referenced members as selectable versions. Members incorporated into a group no longer appear separately in the catalog. Exact name and source matches take priority; when none exists, a group reference may match a unique generic variant from the same source whose name adds the ` (*)` marker. Invalid references are recorded in diagnostics.
- A member's explicit rarity takes precedence. If it is `Unknown` or `Varies`, the member may inherit a known rarity from the group. Evolving item groups may gain an inferred initial version; if that version's rarity cannot be determined, it remains `Unknown`.
- A base item matches a variant only when it meets the requirements, does not match the exclusions, and has a compatible edition. Base items representing package contents are excluded from combinations.
- Effective variant price follows this priority: value expression, multiplier of the base item's value, or sum of the base and variant prices. If the required data is missing, the effective price remains variable (`null`).
- Selecting a group version comes before selecting a variant base. Until a required selection is made, the calculator does not show a final price. The item sheet and calculation use the item resolved from the selected combination.
- A single available base option is selected automatically, including after selecting a group version or filtering content sources. Multiple available bases require an explicit choice. Switching group versions preserves the selected base by its stable base-item identity when compatible with the new version; an incompatible base is cleared.
- Named weapons with a resolvable explicit `baseItem` reference also expose that weapon as a single automatically selected base, including group members and inferred initial stages. Their original price, statistics, text, identity, and artwork are preserved; the displayed price breakdown subtracts the mundane base price from the existing total rather than adding it again. References without an explicit source default to PHB. The usual base-source visibility rules apply.
- Inferred initial stages of evolving variant groups offer the compatible bases of the first referenced variant stage. Their resolved equipment uses the base item's statistics and the group's own description and properties, without later-stage powers. Shared property references from the base and group appear only once, preserving their order and the existing translations of equipment property lists. Initial-stage prices follow the same base-plus-rarity pricing rules as other variants.

References: [groups](src/features/catalog/model/items/build-item-groups.ts), [variants](src/features/catalog/model/items/build-variants.ts), [selection](src/features/catalog/model/items/resolve-item-selection.ts).

## Sources and settings

- Source chips throughout the application use 10 px text by default; existing larger sizes, such as the 12 px chips in the full item sheet, are preserved.
- The Settings dialog uses a left-side navigation on wide screens, with `Local Data`, `Profile`, `Measurement Units`, and `Content Sources` as separate views. The first view, `Local Data`, opens by default and shows Import / Export Data above Reset local data; on narrow screens the navigation appears above the active view. The dialog keeps its maximum available height when switching between views, regardless of their content length.
- Profiles keep source selection, catalog search, filters, sorting, and items per page independently. The `Default` profile always exists and cannot be renamed or deleted. New profiles start with default preferences and become active immediately. Deleting the active profile selects `Default`.
- Available sources are organized by edition (`5e` or `5.5e`) and group. All are selected by default. Source code comparisons ignore letter case and surrounding whitespace.
- Deselecting a source hides its items. It also removes group options originating from that source and variant bases whose source was deselected. A group or variant with no remaining options disappears.
- Profile data is stored in IndexedDB. A legacy source selection is migrated into the `Default` profile. On load, unknown source codes are discarded and the known source order is restored. If storage is unavailable, changes may last only for the current session; if saving a source selection fails, the previous selection is restored.
- IndexedDB database `the-arcane-bazaar` (version 1) stores the complete profile state in the `settings` object store under `profile-state`; the legacy `app-settings` record is migrated. Stored catalog filters are normalized against the same allowed values used by backup validation. Catalog source filters are matched without case or surrounding whitespace and stored in uppercase, while unsupported stored filter values are discarded.
- “Reset local data” asks for confirmation in a warning dialog, then deletes the local database and recreates only the `Default` profile with all sources selected. It also removes the global language preference and restores the browser language.

- The Local Data view can download a versioned JSON backup of all profiles, the active profile, source choices, and catalog preferences. Backup version 2 uses `{ version: 2, data: { profiles, activeProfileId } }` and includes measurement preferences; version 1 is still accepted and initializes missing preferences from the current interface language; each profile contains `id`, `name`, `settings`, and `catalog`. Import first warns that current local data will be overwritten and recommends a backup. It then accepts a JSON file of at most 1 MB, validates its format and profile data, accepts known catalog source codes regardless of case, and replaces the stored profile state. Invalid or unsafe files leave the existing data unchanged.

References: [source registry](src/features/catalog/model/sources.ts), [visibility](src/features/catalog/model/content-visibility.ts), [persistence](src/features/settings/api/settings-database.ts), [settings state](src/features/settings/model/SettingsProvider.tsx), [shared filter schema](src/features/settings/model/catalog-filter-schema.ts), [backup format](src/features/settings/model/settings-backup.ts).

## Measurement units

- System tooltips use the shared `Tooltip` component in `src/components/ui/`, matching the measurement tooltip's dark panel, gold border, typography, spacing, and shadow. They render in a portal above scroll containers, stay within viewport margins, support hover and focus, and dismiss on blur, outside pointer press, or Escape before a parent dialog. Only one tooltip is visible at a time. Measurement and conversion-information triggers also open on click/tap; action-button tooltips close on click while preserving their original action and focus references. This styling also applies to item names, source chips and publication names, image credits, pricing help, toolbar help, and profile action buttons.

- Measurement Units appears immediately below Profile in Settings, with a PencilRuler icon. The unit selectors use two columns on desktop and one on narrow screens, with no hover styling changes. Each profile independently selects imperial or metric units for distance, weight, speed, and liquids. Changes apply immediately, persist in IndexedDB, and are included in version 2 backups.
- New profiles and legacy profiles without valid preferences start metric for Portuguese and imperial for English. Initialization is persisted; changing language later does not change existing choices. A local-data reset uses the resulting browser language for the recreated profile. Version 1 backups receive language-based defaults; version 2 requires all four valid selections.
- Conversions affect presentation only. Source JSON, catalog IDs, names, search data, and price calculations stay unchanged. The parser recognizes numeric measurements, decimals, fractions, ranges, hyphenated dimensions, and compound units in structured values, description paragraphs, and tables. Numeric table cells inherit units from their column heading. Ambiguous ounces remain unchanged unless liquid or mass context resolves them.
- All editions (5e and 5.5e) use the fixed practical conversion table supplied in `tabela_conversao_dd_5e_completa.pdf`, proportionally for unlisted quantities: 1 foot = 0.3 m, 1 mile = 1.5 km, 1 mph = 1.5 km/h, 1 pound = 0.5 kg, 1 fluid ounce = 30 ml, 1 pint = 0.5 L, 1 quart = 1 L, and 1 gallon = 4 L. Units absent from the table retain their existing factors: inches = 2.54 cm, mass ounces = 0.028349523125 kg, square feet = 0.09 m², and cubic feet = 0.027 m³. Cargo tonnage remains unchanged. Other quantities such as time, currency, damage, and AC are not converted.
- An accessible information button beside the Measurement Units heading explains that conversion uses a fixed version 5.5e table. Its localized tooltip opens on hover, focus, or click/tap and closes on leaving the interaction, blur, outside pointer press, or Escape. Escape dismisses the tooltip before the Settings dialog.
- Measurements are gold and underlined, with an accessible comparison tooltip on hover, keyboard focus, or click/tap. Escape closes the tooltip before the item sheet. Inline linear feet display grid squares in both systems (feet / 5), including fractional squares and both endpoints of weapon ranges. In the tooltip, the Imperial and Metric lines show only their respective measurements; squares appear once on a separate `Grid Squares: (8)` line (localized), without repeating the square conversion formula. For example, a 20/60-foot range shows `Imperial: 20/60 ft.`, `Metric: 6/18 m`, and `Grid Squares: (4/12)`. Miles, inches, areas, and volumes do not show squares.
- Display uses the interface locale, up to one decimal place without trailing zeros, and additional precision when needed to avoid rounding a positive value to zero. Liquid amounts below 1 L use ml. Conversions always start from original values. Cost denominators convert their original quantity (for example per mile becomes per 1.5 km) without changing the associated price.

## Search, filters, and navigation

- The initial route `/` shows a responsive landing page beneath the shared toolbar, with its own scroll area, a full-width fantasy tabletop background behind centered hero text and actions. The background keeps its full image height on wide screens, extends behind the start of the features section without changing section positions, and fades into the page background at its lower edge. The page also shows feature summaries, a static screenshot of the real catalog, an opaque Merchant coming-soon card, and a final call to action over a full-width panoramic fantasy landscape with the estimated-prices disclaimer below its catalog button. The landscape is cropped proportionally to a shorter height, extends behind the content above on wide screens, and fades into the page background at its upper edge. Both catalog calls to action navigate to `/catalog`, respecting the deployment base path. The features link scrolls to the resources section and respects reduced-motion preferences. Home text and the catalog screenshot follow the interface language (English or Brazilian Portuguese); screenshots illustrate a selected item and its price calculator, independently of current profile preferences. The Merchant section is informational and does not start a trading workflow.
- Primary navigation appears beside the project brand, with House, BookOpen, and Store icons for Home, Catalog, and Merchant. Desktop links show the active page; below the medium breakpoint, a navigation button opens the same links. Labels follow the interface language.
- Selecting Merchant normally opens a dismissible Coming Soon notice over the current page without changing its URL or catalog state. Direct access to `/merchant` redirects to Home and opens the notice once. Closing it does not reopen it on subsequent navigation. Modified link clicks retain the real `/merchant` destination.
- The mobile navigation closes on selection, Escape, outside click, or focus leaving the navigation. The Merchant notice closes with its close button, Escape, or backdrop; focus returns to its desktop link or mobile navigation button.

- Search matches Portuguese and English item names, visible group and base-option names, and original tags without distinguishing letter case or accents. Type, rarity, category, and source also participate in filtering. Switching language recalculates the list and returns pagination to its first page while preserving an available selected item.
- Only one item type is selected at a time; the screen starts with `Common`. Available rarities, categories, and sources are calculated from visible items of the selected type. Incompatible selections are removed when the type or available sources change.
- Item Type uses a two-segment radio control with Magic on the left and Mundane on the right. The selected segment has a subtle matching violet or slate fill and inset outline; the unselected segment has a dark inset shadow and reduced brightness across its background, icon, text, and border. Hover partially restores its brightness, and focus restores full brightness for keyboard visibility. Both segments reuse the existing TypeMark icons, 11 px text, font, spacing, and colors; native radio keyboard navigation and a visible keyboard-focus outline are preserved.
- The Item type and Category filter sections start expanded. Category also expands when switching to `Magic`.
- Rarity keeps its collapsible, initially closed multi-select filter and displays only available rarities. Standard rarities appear in canonical order beside a vertical rail whose segments use their existing rarity colors. The scale container and its option rows have square corners. Varies and Unknown appear separately in two columns below a gold divider when standard rarities are present, with each checkbox and label centered together in its column. Selected options have a subtle background tint in their rarity's text color, strengthened on hover or focus. Checkbox borders and selected checkmark icons match their rarity's text color, with dark backgrounds and a visible keyboard-focus outline. Each checkbox remains independent; the rail is decorative and does not select a range. Labels follow the interface language.
- Category filter options are sorted alphabetically by their displayed names using the selected interface locale. Switching languages immediately reorders them, preserves selected internal category values, and keeps `All` first.
- Selecting `All` for categories or sources clears only the selections in that group. Multiple selected categories act as alternatives: an item needs to belong to any one of them.
- The list starts sorted by displayed name in ascending order using the selected locale. It can also be sorted by type, category, rarity, and price; items without a price come last when sorting by price in ascending order. All sort modes use displayed names as a tie-breaker, and stable IDs break equal-name ties. Group and base selectors also use stable option IDs to break equal-label ties.
- Pagination starts at 20 items per page and offers 10, 20, 50, and 100. Changing filters, sorting, or page size returns to the first page. Search, filters, sorting, and page size are restored for the active profile; page number and selected item are not stored.

## Price calculation

- The calculator requires a finite base price **greater than zero**. If an item has no base price, the user may enter a manual value in GP. An explicit price of zero remains valid in the catalog but produces no calculator result; the manual value is used only when the base price is `null`.
- With no adjustments, buying costs 100% of the base price and selling returns 50%. Buying (`B`) and selling (`S`) percentage adjustments are summed separately. Each total is limited to the range from -90% to +300%.
- Economy, market, party reputation, and negotiation apply to all items. Magic frequency applies only to `Magic` items. Custom modifiers apply the same percentage to buying and selling.
- Built-in price adjustments carry group and option identifiers separately from their English labels. The UI translates their option labels and breakdown without changing the underlying percentages; custom modifier names are preserved.
- The default options (`stable`, `regular`, `neutral`, `standard`, and `standard`) apply 0%. The other currently implemented options are:

| Group | Option | Buy | Sell |
| --- | --- | ---: | ---: |
| Economy | `prosperous` | +20% | +20% |
| Economy | `depressed` | -10% | -10% |
| Market | `competitive` | -20% | -15% |
| Market | `blackMarket` | +35% | +30% |
| Market | `restricted` | +25% | +25% |
| Reputation | `despised` | +12% | -12% |
| Reputation | `mistrusted` | +6% | -6% |
| Reputation | `honored` | -6% | +6% |
| Reputation | `admired` | -12% | +12% |
| Negotiation | `success` | -10% | +10% |
| Negotiation | `failure` | +10% | -10% |
| Magic frequency | `rare` | +25% | +25% |
| Magic frequency | `abundant` | -15% | -15% |

- Formulas: `buy = base price × (1 + B/100)`; `sell = base price × 0.5 × (1 + S/100)`. Results are rounded to thousandths of a CP and can be displayed in GP, SP, and CP (`1 GP = 10 SP = 100 CP`).
- Changing the selected item resets the modifiers and manual price. Changing the group version or variant base clears the manual price.
